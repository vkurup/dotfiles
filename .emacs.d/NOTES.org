#+TITLE: Emacs config notes
#+STARTUP: overview

Roadmap, ideas and a changelog for =init.el=. The config is shared between
the Linux home machine and the work Mac, so changes should work on both:
gate machine-specific bits on =system-type= (or =executable-find=) rather
than hard-coding paths.

* Regression tests
=test/run-tests.sh= loads the real =init.el= in a batch Emacs (no server,
no secrets, nothing saved on exit) and runs every =test/*-test.el=.
Takes a few seconds; run it after changing =init.el= on either machine.
- =test/run-tests.sh beancount/= runs only tests whose names match.
- When something I rely on breaks, add a test for it before fixing it.
  Copy a test in =test/beancount-test.el=: =vk-with-temp-file= opens a
  temp file as if I'd visited it, =vk-press= presses a key binding.
- New area of use (org, magit, ...) → new =test/<area>-test.el=.

* Roadmap
** TODO Emacs as an LLM harness [1/4]                                :llm:
Current priority. Three different things this can mean:
- *LLM in Emacs*: chat with / rewrite text in any buffer.
- *Agent in Emacs*: run a coding agent (Claude Code etc.) with Emacs as its
  UI: diffs, file context, approvals.
- *Agent driving Emacs*: the agent calls back into the running Emacs
  (emacsclient / MCP) to read buffers, run commands, use xref/LSP.
Plan:
- [ ] *gptel*: general-purpose LLM client (Anthropic, OpenAI, Ollama...).
  Chat in any buffer, region rewrite, presets, tool use, MCP via =mcp.el=.
  Needs an API key; keep it in =~/.authinfo.gpg= (not the repo).
- [X] *agent-shell*: native Emacs buffer for ACP agents (Claude Code,
  Gemini CLI, ...). Installed 2026-10-31; uses the Claude Code login.
  - Start: =C-c A= (=agent-shell=); =C-u C-c A= forces a new session.
  - In the buffer: =RET= send (queues if busy), =M-RET= steer the running
    turn, =M-J= newline, =C-c C-c= interrupt, =C-c C-v= model,
    =C-c C-m= session mode, =C-c C-o= toggle shell/viewport.
  - Needs the adapter on each machine:
    =npm install -g @agentclientprotocol/claude-agent-acp=
    (then =asdf reshim nodejs=, or nothing with mise), plus one =claude=
    login outside Emacs.
  - Debug: =M-x agent-shell-toggle-logging=, then =agent-shell-view-traffic=.
  - Image paste on Linux needs =wl-clipboard= (Wayland) or =xclip= (X11).
- [ ] Alternative to compare: *claude-code-ide.el*: runs the Claude Code CLI
  in vterm/eat and exposes Emacs (xref, diagnostics, ediff diffs) to it over
  MCP.
- [ ] Decide what to keep; write up keybindings and workflow here.
Notes:
- Claude Code CLI is installed (=~/.local/bin/claude=) and can already
  reach this Emacs via =emacsclient --eval=.
- Must work on the work Mac too (auth, model/provider may differ there).
** TODO Investigate modern completion setups
Selectrum is deprecated (its author recommends vertico), so the minibuffer
completion stack needs replacing. Look at what's current before picking:
- *vertico* (minibuffer UI) + *orderless* (matching) + the existing
  *marginalia*; or keep prescient's sorting via =vertico-prescient=.
- *consult* (better =C-x b=, search, imenu, ...) and *embark* (actions).
- Built-in options in Emacs 29/30 (=fido-vertical-mode=, =icomplete=).
- In-buffer completion is a separate choice: see "company vs corfu".
smex was removed 2026-11-01; =M-x= history comes from savehist.
** TODO Decide: lsp-mode vs eglot
eglot is built into Emacs 29. Try it for clojure (clojure-lsp) and python
before deciding; would also let elpy go.
** TODO Replace elpy
Found 2026-11-01: elpy has never actually been turned on. Its =:bind=
makes use-package defer it and nothing loads it, so =elpy-enable= never
runs; Python files get plain python-mode. elpy is largely unmaintained. Candidates: eglot + pyright/basedpyright or
ruff, with direnv handling the venv.
** TODO Look at tree-sitter major modes
Emacs 29 ships =*-ts-mode= variants (python, yaml, typescript, ...).
=treesit-auto= can install grammars and remap modes.
** TODO Revisit undo-tree
Built-in =undo-redo= plus =vundo= is lighter; undo-tree history files
have been a source of slowness/corruption for some people.
** TODO company vs corfu
Optional. corfu + cape is the lighter-weight modern pairing with vertico.

** TODO Package archive hygiene

* Ideas / someday
** Magit-style UX elsewhere                                          :ux:
Magit's popup menus come from =transient=, a separate library that other
packages use too. Add ready-made transient menus wherever possible instead
of writing elisp:
- *casual-suite*: transient menus for dired, ibuffer, isearch, calc, info,
  bookmarks, agenda, re-builder. Bind each to =C-o= in its mode.
- *gptel*: =gptel-menu= is already a transient (fits the LLM roadmap item).
- *disproject*: a transient menu for project.el/projectile commands.
- *embark*: =C-.= on any thing (file, symbol, URL, buffer) brings up its
  actions, like magit's "act on the thing at point". Pairs with vertico.
- A personal launcher transient (one key → my most-used commands:
  rg, agent-shell, vterm, timemachine, ...). Takes about 15 lines of
  =transient-define-prefix=.
- which-key is already on and covers the "what can I press next?" half.

* Changelog
** 2026-11-01 (cleanup step 5: deferred loading)
- Language and occasional-use packages load when first needed (=:defer=,
  =:hook=, =:mode=, =:after=) instead of at startup. Batch startup went
  from ~1.56s to ~1.05s. Remaining big ones: recentf, projectile.
- paredit in elisp only worked because clj-refactor loaded it at startup;
  it now has its own =:hook=. =test/languages-test.el= guards this.
- rg's default bindings did nothing (their one key, =C-c s=, is crux's),
  so rg is just deferred and no longer has to load before crux. rg has a
  magit-style transient menu, =rg-menu=, if I want a key for it.
- Checked by opening ~25 file types under the old and new config and
  comparing major mode, minor modes and key bindings: identical.
** 2026-11-01 (cleanup step 4: outline sections)
- =init.el= is grouped into =;;;= sections (=;;;;= for each language), in
  load order: packages, environment, general, appearance, keys, projects,
  editing, checking, completion, files/windows, VC, terminals/agents,
  languages, writing, local files, org, finance, demos, server/custom.
- Order matters in two places: =diminish= and =exec-path-from-shell= must
  load first, and rg must load before crux so =C-c s= stays
  =crux-ispell-word-then-abbrev= (rg's default bindings also want it).
- Checked by loading old and new =init.el= in batch and diffing every
  global key binding, hook and variable: only ordering differed.
** 2026-11-01 (cleanup step 3: custom-file)
- M-x customize and package installs now save to =custom.el= (git-ignored,
  per machine) instead of the bottom of =init.el=, so
  =package-selected-packages= no longer causes merge conflicts.
- Settings I want everywhere moved to plain =setq='s in =init.el=:
  =js-indent-level=, =sh-basic-offset=, =org-agenda-files= (now includes
  trips.org), extra lsp ignored dirs (=screenshots=, =logs=) on top of
  lsp-mode's current defaults.
- Dropped =custom-safe-themes= (=load-theme= already skips the prompt) and
  =typescript-indent-level= (typescript-mode isn't installed).
- On a new machine, Emacs asks once before trusting =.dir-locals.el=
  values (e.g. the work inf-clojure ones); answer =!= to save to custom.el.
** 2026-11-01 (cleanup step 2: dead code)
- Removed ledger-mode (I use beancount), smex, racket-mode, rust-mode,
  writeroom-mode, inf-clojure, ERC/freenode, the file-notify workaround,
  =lib/nano-*.el= and old commented-out code (git history has it).
- =esk-cleanup-buffer= is gone: use =C-c n= (crux), which now cleans the
  whole buffer when no region is active. =C-x C-r= is =crux-sudo-edit=
  (edits the current file as root; =C-u C-x C-r= asks for a file).
- =.ts= files open in web-mode with tide, like =.tsx=.
